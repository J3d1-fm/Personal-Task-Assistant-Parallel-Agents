Personal Task Tracker Technical Documentation

Version: 0.2.3
Last updated: 2026-06-01

Overview

Personal Task Tracker is a FastAPI application with a server-rendered HTML shell, static CSS/JS assets, and JSON API endpoints for task creation, task updates, context ingestion, and reminders.

Version 0.2.3 keeps the backend data model unchanged, fixes responsive panel overlap, and adds a destructive Dismiss action for removing tasks from storage. The first screen answers what is active, what is overdue, who owns the next action, what needs review, and what the task colors mean.

Runtime Behavior

Task loading still calls:

GET /api/tasks?include_done=true

Task creation still calls:

POST /api/tasks

Task updates still call:

PATCH /api/tasks/{task_id}

Task dismissal calls:

DELETE /api/tasks/{task_id}

Dismiss is a hard delete. It removes the task document or SQLite row from the active store and does not create an audit record.

The browser UI computes these display-only concepts locally:

- Active tasks: all tasks where status is not done.
- Overdue tasks: active tasks with due_at or reminder_at earlier than the current browser time.
- Due-soon tasks: active tasks with due_at or reminder_at within the next 24 hours.
- My next actions: active tasks assigned to me.
- Codex work: active tasks assigned to codex.
- Needs review: tasks with waiting_review status.
- Unassigned: active tasks with unassigned assignee.

Storage And Retention

Production storage:

- Cloud Run runs the FastAPI app.
- `TASK_STORE=firestore` selects the Firestore backend.
- Task records are stored in the Firestore collection `tasks`.
- The numeric task id counter is stored in Firestore at `metadata/task_counter`.
- There is no TTL, retention job, or archive job in the current code.

Local development storage:

- `TASK_STORE=sqlite` selects the SQLite backend.
- Tasks are stored in the local SQLite file configured by `DATABASE_URL`, usually `task_tracker.db`.

History behavior:

- `created_at`, `updated_at`, `completed_at`, source fields, and source context are stored on each task.
- Done tasks remain in storage indefinitely unless deleted.
- Dismiss deletes the task permanently.
- There is no separate event history for status changes, owner changes, deletes, or reminder sends.

Spreadsheet option:

The tracker can be backed by Google Sheets, but a spreadsheet is a weaker operational database than Firestore. It is reasonable for a human-readable archive or append-only history export. It is riskier as the primary live store because concurrent writes, id generation, filtering, deletes, API latency, and auth boundaries become more fragile.

Recommended spreadsheet path if needed:

- Keep Firestore as the live task store.
- Add an append-only Google Sheets history/export sync for created, updated, completed, dismissed, and reminder events.
- Use Sheets for review/reporting and Firestore for the live queue.

Local Development Auth

When `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET` are empty, and the app is not considered hosted, the browser UI creates a local session automatically.

The app is considered hosted when any of these are true:

- Firestore is enabled through `TASK_STORE=firestore`.
- `SESSION_COOKIE_HTTPS=true`.
- `PUBLIC_BASE_URL` starts with `https://`.

The local session email is the first configured `ALLOWED_GOOGLE_EMAILS` value, or `local-dev@task-tracker.local` if no allowlist is configured.

This fallback is intended only for local development so the UI can be inspected at `http://127.0.0.1:8000/` without creating Google OAuth credentials.

No database migration is required for version 0.2.3 because the dismiss endpoint already existed in the API and both storage backends already implement delete_task.

Rollback Notes

To roll back version 0.2.3, revert these files to the previous version:

- app/config.py
- app/main.py
- app/templates/index.html
- app/static/app.js
- app/static/styles.css

The changelog and this technical documentation can remain as history or be reverted with the same version rollback.
